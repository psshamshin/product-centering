# Центровка фото товара (DOOH)

Прототип автопозиционирования товара на баннере. Берёт JSON экспорта проекта DOOH и возвращает тот же JSON, где у контейнера «Фото товара» (`product-image`) пересчитаны `x`, `y`, `w`, `h`. Остальные поля не меняются.

Всё считается в браузере: JSON и PNG никуда не отправляются, сервер для расчёта не нужен.

## Файлы

- `index.html` — интерфейс.
- `engine.js` — ядро расчёта без DOM. Работает в браузере (`window.ProductCentering`) и в Node (`require('./engine.js')`).
- `config.example.json` — все настройки со значениями по умолчанию.

## Запуск у себя

Открыть `index.html` в браузере двойным кликом.

## Публикация на GitHub Pages

1. На github.com: **New repository** → имя, например `product-centering` → **Create repository**.
2. На странице репозитория: **uploading an existing file** → перетащить `index.html`, `engine.js`, `config.example.json`, `README.md` → **Commit changes**.
3. **Settings → Pages** → Source: **Deploy from a branch**, Branch: **main**, папка **/ (root)** → **Save**.
4. Через 1–2 минуты страница откроется по адресу `https://<логин>.github.io/product-centering/`.

На бесплатном аккаунте Pages работает только для публичных репозиториев: код и страница будут видны всем. Данных WB в файлах нет — встроенный пример обезличен.

## Ядро для разработчиков

```js
const fs = require('fs');
const sharp = require('sharp');            // npm i sharp — только для режима с PNG
const E = require('./engine.js');

(async () => {
  const project = JSON.parse(fs.readFileSync('layouts-import.json', 'utf8'));
  const layoutIds = E.listLayouts(project).filter(l => l.hasProduct).map(l => l.layoutId);

  // Без PNG: контейнер = самая крупная свободная область
  const cfg = JSON.parse(fs.readFileSync('config.json', 'utf8'));   // необязательно: можно передать {}
  const plain = E.applyToProject(project, layoutIds, cfg);

  // С PNG: нужен альфа-канал копии PNG до 256 px по длинной стороне
  const meta = await sharp('product.png').metadata();
  const { data, info } = await sharp('product.png')
    .resize({ width: 256, height: 256,   // = tuning.analysisSize
            fit: 'inside', withoutEnlargement: true })
    .ensureAlpha().extractChannel('alpha').raw()
    .toBuffer({ resolveWithObject: true });
  const analysis = E.analyzeProduct(data, info.width, info.height, meta.width, meta.height, cfg);
  const res = E.applyToProject(project, layoutIds, cfg, { width: meta.width, height: meta.height, analysis });

  fs.writeFileSync('layouts-import-centered.json', JSON.stringify(res.project, null, 2));
  res.results.forEach(r => console.log(r.layoutName, r.ok ? r.after : r.error));
})();
```

## Настройки

Все константы передаются снаружи третьим аргументом `computeLayout` / `applyToProject` (и в `analyzeProduct`). Полный объект со значениями по умолчанию — в `config.example.json`, в интерфейсе — «Параметры расчёта → Все настройки в JSON».

Правила слияния:
- передавать можно только нужные поля, остальное берётся по умолчанию;
- некорректное значение (не число, не true/false) игнорируется, остаётся значение по умолчанию; предупреждение попадает в `result.warnings` с префиксом «Настройки:»;
- неизвестные параметры верхнего уровня пропускаются с предупреждением;
- `E.resolveOptions(cfg)` возвращает итоговый объект и список предупреждений — удобно проверять конфиг до расчёта.

Основные параметры:

| Параметр | По умолчанию | Что делает |
|---|---|---|
| `margin` | 16 | Поле от краёв холста, px |
| `padding` | 8 | Отступ от элементов без PNG и для тонких частей товара, px |
| `clearance` | 40 | С PNG: воздух между массой товара и элементами, px |
| `fill` | 0.9 | С PNG: доля от максимально возможного размера |
| `thinCrop` | true | Тонкие части можно обрезать краем кадра |
| `thinRatio` | 0.22 | Порог «тонкой» части от толщины самой толстой |
| `anchor` | `auto` | Обрезанное фото: `auto` — определить по PNG, `bottom` / `top` / `left` / `right` — задать край, `none` — не учитывать |
| `disclaimerIsObstacle` | false | Дисклеймер — препятствие |
| `hugText` | `['price-badge']` | Плашки, которые в рендере сжимаются по тексту: если контейнер в JSON шире текста, берётся ширина по тексту |
| `wideIgnore` | `ratio` 0.6, `ratios` {price-badge: 0.4, strikethrough-price: 0.35}, `areaRatios` {product-description: 0.12} | Элемент из `types` шире порога по ширине (`ratios` — свои пороги для типов) или описание больше порога по площади холста получает «не учитывается». 0 — выключено. Явная роль слоя важнее |
| `splitHeadlineIsSoft` | false | Под заголовок с `splitByProductImage` товар может заходить |
| `useSafeZones` | true | Учитывать `settings.safeZones` сцены |
| `widthFactors` | лого 1.7, скидка 2.5, CTA 2.07… | Ширина = коэффициент × высота, если в JSON нет `w` |
| `textMetrics` | `{}` | Переопределение метрик текста по типу: `{ charW, lineH, pad, placeholder }` |
| `tuning` | см. `config.example.json` | Внутренние константы алгоритма: допуски обрезки, «центр важнее размера» (`centerKeep` 0.8), баланс, размер копии PNG и др. |

### Какие слои учитываются

Роль слоя: `obstacle` — товар обходит целиком, `thin` — масса обходит, а тонкие части (ручка, шнур) могут проходить под слоем, `soft` — товар может заходить под слой, `ignore` — не учитывается, `auto` — по умолчанию.

- `roles` — по типу элемента для всех лейаутов: `{ "disclaimer": "obstacle", "media": "ignore" }`.
- `layers` — для конкретного слоя, сильнее `roles`. Ключ — `id` элемента, `"<layoutId>/<индекс в elements>"` или `"<layoutId>/<тип>"`. Значение — роль или `true` / `false` (учитывать / не учитывать).

```json
{
  "roles": { "disclaimer": "obstacle" },
  "layers": {
    "6ae262a818f039ea9a541431/4": "ignore",
    "6ab276f5f49c22afc64c5db9/wb-logo": false
  }
}
```

Без настроек роли такие: фон, градиент, слайдшоу, служебные — не учитываются; дисклеймеры — `soft`; заголовок, старая цена, описание — `thin`; выключенные (`enabled: false`) — не учитываются; остальное — `obstacle`. Фото товара (`product-image`) всегда пересчитывается. В результате у каждого элемента есть `info.role`, `info.defaultRole` и `info.override`.

## Как считается

1. **Элементы.** Все элементы, кроме фона и служебных, — препятствия; дисклеймер — «мягкий», товар может заходить под него. Если в JSON нет ширины или высоты, размер оценивается: лого, скидка, «цена и кнопка» — по высоте, тексты — по кеглю и длине текста. Тексты с шириной `w` переносятся по словам, высота растёт по числу строк. Медиа учитывается, если у него есть контент (`contentUrl`, `url`, `src` и т. п.); без ширины в JSON — ширина 2,7 × высота (`widthFactors.media`).
2. **Масса и тонкие части (с PNG).** Силуэт делится на плотную часть (щётка, корпус) и тонкие части (ручка, шнур). Тонкое — всё, что тоньше 22% самой толстой части или 6% длины силуэта (`tuning.thinLength`): так длинная ручка тонкая, даже если насадка тоже плоская. Если иначе товар не встаёт по центру главной свободной зоны или выходит в 1,5+ раза мельче, тонкие части могут пройти под элементами (до `tuning.thinUnderMax`, 60%) и уйти за край кадра.
3. **Размер.** Масса — как можно крупнее, но не ближе 40 px к элементам. Тонкие части не должны задевать элементы. Если по центру холста товар выходит не мельче 80% от максимума — он ставится по центру. Итог × 0,9 — запас воздуха.
4. **Обрезанное фото.** Край PNG считается обрезанным, если видимые пиксели касаются его (≥ `tuning.cutEdgeMin`, 2% длины края), а противоположный край свободен. Дальше два случая:
   - край перерезан **массой** (человек по пояс): этот край прижимается к такому же краю холста и может уйти за него ещё на `tuning.anchorCrop` (20%) видимой высоты; под элементы не заходит только часть силуэта у противоположного края — `tuning.anchorProtect` (45%: голова, лицо);
   - край перерезан **тонкой частью** (ручка швабры): под элементы может уходить только эта тонкая часть, масса — нет. Пробуются два варианта: прижать край к краю холста или спрятать обрезанный конец под элемент (заголовок, цену) — выбирается прижатый, если он не мельче `tuning.anchorKeep` (70%) и не хуже по центровке.
   Поддерживаются все четыре края; `anchor` в настройках задаёт край вручную или выключает проверку.
5. **Место.** Ближе всего к вертикальной оси холста, где воздуха достаточно. По вертикали — ровные зазоры сверху и снизу, снизу чуть больше.

## Принятые правила и как их откатить

Каждое правило включено по умолчанию и выключается или меняется через настройки (третий аргумент ядра или «Все настройки в JSON» в интерфейсе) — код трогать не нужно. Номер модуля виден в заголовке страницы (`E.MODULE_VERSION`).

| № | Правило | Почему | Параметр (по умолчанию) | Как откатить |
|---|---|---|---|---|
| 1 | Масса товара держится от элементов на 40 px, тонкие части — на 8 px | Товар не прилипает к тексту | `clearance` 40, `padding` 8 | Задать свои значения |
| 2 | Итоговый размер — 90% от максимально возможного | Запас воздуха вокруг товара | `fill` 0.9 | `fill: 1` — максимальный размер |
| 3 | Силуэт делится на массу и тонкие части: тонкое уже 22% самой толстой части или 6% длины силуэта | Ручки и шнуры не раздувают рамку товара | `thinRatio` 0.22, `tuning.thinLength` 0.06 | `tuning.thinLength: 0` — только по толщине |
| 4 | Бахрома и кромка вплотную к массе считаются массой | Края насадки не срезаются краем кадра | `tuning.fringe` 0.8 | `tuning.fringe: 0` |
| 5 | Тонкие части можно обрезать краем кадра, если масса станет крупнее в 1,5+ раза | Крупная щётка вместо мелкой швабры целиком | `thinCrop` true, `tuning.cropGain` 1.5, `tuning.cropMax` 0.9 | `thinCrop: false` — товар всегда целиком |
| 6 | По центру холста, если так товар не мельче 80% от максимума; центр массы — в главной свободной зоне | «По центру, если влезает» | `tuning.centerKeep` 0.8, `tuning.axisTolerance` 0.04 | `tuning.centerKeep: 1` — всегда максимальный размер, где угодно |
| 7 | Среди мест с достаточным воздухом выбирается ближайшее к оси холста; снизу воздуха чуть больше, чем сверху | Оптический центр, ровные зазоры | `tuning.airOk` 0.5, `tuning.opticalBottom` 1.1 | `tuning.opticalBottom: 1` — ровно |
| 8 | Зазоры по сторонам считаются по полосам силуэта, а не по рамке | Хвост или ручка не «прячут» соседний элемент (котёнок на Хаммерах) | — | Не откатывается (исправление ошибки) |
| 9 | Роли по умолчанию: фон и служебные — не учитываются; дисклеймер — товар может заходить; заголовок, старая цена, описание — масса обходит, ручка может заходить (`thin`); остальное — обходит | Текст поверх ручки допустим, поверх массы — нет | `roles`, `layers` | `roles: { "headline": "obstacle", … }` |
| 10 | Широкие плашки не учитываются: цена шире 40% холста, старая цена шире 35%, бейджи/кнопка/скидка шире 60%, описание больше 12% площади (с 1.8 — старая цена 35%) | Иначе товару негде встать (Ситиформат, Суперсайт) | `wideIgnore` | `wideIgnore: { "ratio": 0, "ratios": { "price-badge": 0, "strikethrough-price": 0 }, "areaRatios": { "product-description": 0 } }` (пустой `{}` не сбрасывает пороги — нужны нули) |
| 11 | Цена сжимается по тексту, её кегль считается от высоты, а не от `fontSize` | В JSON `fontSize` цены в других единицах (483 при h = 100) | `hugText` ['price-badge'] | `hugText: []` |
| 12 | Тексты с шириной переносятся по словам, высота растёт по числу строк | Описание в рендере идёт в 2 строки | `textMetrics` | Нет отдельного выключателя |
| 13 | Медиа учитывается по рамке, даже если `contentUrl` пустой; без ширины — 2,7 × высота | В экспорте ссылка на медиа пустая, а в рендере блок есть | `mediaNeedsContent` false, `widthFactors.media` 2.7 | `mediaNeedsContent: true` |
| 14 | Обрезанное фото: край с видимыми пикселями (≥ 2% длины, противоположный свободен) — обрезанный | Человек по пояс, ручка за кадром | `anchor` 'auto', `tuning.cutEdgeMin` 0.02 | `anchor: "none"` |
| 15 | Обрезано массой (человек) — край прижимается к краю холста, под элементы не заходит 45% силуэта у противоположного края; по центру, если не мельче 60% | Лицо всегда видно, человек не жмётся к краю | `tuning.anchorProtect` 0.45, `anchorCrop` 0.2, `anchorCenterKeep` 0.6 | Поменять значения или `anchor: "none"` |
| 16 | Обрезано тонкой частью (ручка) — либо прижать к краю холста, либо спрятать конец под элемент; прижатый вариант, если не мельче 70% и не хуже по центру | Ведро со шваброй под заголовком | `tuning.anchorKeep` 0.7 | `tuning.anchorKeep: 0` — прижимать, если не хуже по центру |
| 17 | Без PNG контейнер занимает самую большую свободную область | Режим до анализа силуэта | `margin` 16, `padding` 8, `minSide` 80 | — |
| 18 | (1.9) Кончики тонких частей рядом с массой (край насадки) не выходят за поле холста — как сама масса | Насадка не обрезается краем кадра (Щит, Хаммеры) | `tuning.nearCore` 4 | `tuning.nearCore: 0` |
| 19 | (1.9) «По центру» — центр массы в средней части главной свободной зоны; ручку можно обрезать краем кадра, чтобы масса встала по центру, даже без выигрыша в размере | Масса в центре композиции, а не внизу (Ситиформат) | `tuning.zoneCenterBand` 0.25 | `tuning.zoneCenterBand: 0.5` — вся зона |
| 20 | (1.9) Медиа по умолчанию — роль `thin`: масса обходит, ручка может заходить | Ручка под логотипом партнёра допустима (Метро 2160) | `roles.media` | `roles: { "media": "obstacle" }` |
| 21 | (1.10) Ряд плашек (бренд, цена с кнопкой, цена, банк) в одну строку шириной ≥ 75% холста не учитывается целиком | Товар опускается к центру, плашки ложатся поверх (Метро 1080) | `wideRow` { ratio: 0.75, types } | `wideRow: { "ratio": 0 }` |
